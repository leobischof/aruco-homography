# CI/CD — Prüfschranke, Werkbank, Auslieferung

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development
> (recommended) or superpowers:executing-plans to implement this plan task-by-task.
> Steps use checkbox (`- [ ]`) syntax for tracking.

**Ziel:** Ein Push nach `master` erzeugt ohne weiteres Zutun eine Marke, eine
GitHub-Fassung mit Installer · APK · Browser-Bau und einen aktualisierten
F-Droid-Bestand — und ein Pull Request mit roten Tests lässt sich nicht mehr mergen.

**Architektur:** Die Werkbank definiert **keinen** Projektbefehl selbst. Sie richtet die
Werkzeugkette her und ruft dann in `dev.ps1` hinein, genau wie `.vscode/tasks.json` es
tut (`AGENTS.md`, „Kommandos"). Weil `dev.ps1` an Windows-PowerShell hängt — der
Android-Kreuzbau holt `cmake` und `ninja` aus der Visual-Studio-Installation — laufen
**alle Bau-Aufgaben auf `windows-latest`**. Nur die F-Droid-Veröffentlichung läuft auf
Ubuntu, weil dort nichts aus `dev.ps1` gebraucht wird. Drei Bau-Anlässe (Fassung,
Nachtbau, Handstart) teilen sich **eine** Baubeschreibung (`build.yml` per
`workflow_call`), und das Herrichten der Werkzeugkette steht in zwei zusammengesetzten
Aktionen statt dreimal im Ablauf.

**Tech Stack:** GitHub Actions (`windows-latest` = Windows Server 2025, `ubuntu-latest`),
PowerShell 5.1, Python 3.13 + pytest, Node 22, CMake/Ninja aus Visual Studio Enterprise
2022, Android SDK + NDK, OpenCV 5.0.0 (fertige SDKs von GitHub), Inno Setup 6 über
Chocolatey, `fdroidserver`, GitHub Pages.

**Vorlage:** [`docs/superpowers/specs/2026-09-14-ci-cd-design.md`](../specs/2026-09-14-ci-cd-design.md)

## Task 1: Der Release-Schlüssel wird nicht mehr aus Versehen neu erfunden

**Das ist der wichtigste Schritt des ganzen Plans und steht deshalb zuerst.**
`Enable-ReleaseSigning` legt heute einen Schlüssel **an**, wenn keiner da ist. Auf diesem
Rechner ist das richtig. In einer Werkbank hieße ein fehlendes Geheimnis: jede Fassung
trägt eine andere Signatur, kein Gerät kann je aktualisieren, und der Bau bleibt grün.

**Files:**
- Modify: `dev.ps1:744` (`$AndroidSigningDir`)
- Modify: `dev.ps1:970-1003` (`Enable-ReleaseSigning`)

**Interfaces:**
- Produces: zwei Umgebungsschalter, auf die alle späteren Aufgaben bauen —
  `ARUCO_SIGNING_DIR` (wo der Schlüssel liegt) und `ARUCO_REQUIRE_EXISTING_KEY=1`
  (Anlegen verboten; das Kennwort kommt dann aus `ARUCO_KEYSTORE_PASSWORD`).

- [ ] **Step 1: Den Ablageort umstellbar machen**

In `dev.ps1` diese Zeile:


```powershell

# ihren Arbeitsbereich aus und zeigt mit ARUCO_SIGNING_DIR hierhin.
```

- [ ] **Step 2: Den Riegel einbauen** — *umgesetzt, und anders als hier ursprünglich stand*

> **Diese Aufgabe ist erledigt (Commits `9af9f76`, `7672295` und der Nachtrag darauf).
> Der Code steht in `dev.ps1`, `Enable-ReleaseSigning`, und nicht mehr hier.**
>
> Hier stand ein Codeblock mit `if ($env:ARUCO_REQUIRE_EXISTING_KEY -eq '1')` und den
> Meldungstexten dazu. **Beides ist überholt**, und der Block wird nicht durch die neue
> Fassung ersetzt: Ein Plan, der Code doppelt, der schon im Repo steht, ist die zweite
> Fassung davon — und die zweite Fassung läuft weg, sobald jemand nur eine anfasst.
>
> Was sich gegenüber dem ursprünglichen Text geändert hat, und warum:
>
> | Ursprünglich | Jetzt | Grund |
> |---|---|---|
> | Zwei unabhängige Schalter | **Gekoppelt**: der Riegel greift, sobald `ARUCO_SIGNING_DIR` **oder** `ARUCO_REQUIRE_EXISTING_KEY` gesetzt ist | Wer den Ablageort setzt und den Riegel vergisst, bekam genau die Falle zurück — an einem anderen Ort. > | `-eq '1'` | greift bei jedem Wert außer leer und `'0'` | YAMLs Wahrheitswert heißt `true`. Ein Sicherheitsschalter, der nur eine Schreibweise versteht, ist der, den der Nächste still abschaltet. |

## Task 2: `check-apk-release` sieht nach, WELCHER Schlüssel es war

`Invoke-CheckApk` schließt heute den einen falschen Schlüssel aus, den jedes SDK
mitliefert. Es schließt nicht aus, dass irgendein **anderer** benutzt wurde. Task 1
verhindert, dass *kein* Schlüssel da ist; diese Aufgabe verhindert, dass der *falsche*
da ist — und zwar am Erzeugnis, nicht am Bauweg.

**Files:**
- Modify: `dev.ps1`, in `Invoke-CheckApk`, zwischen dem `$debugSigned`-Block und
  `if ($Release) { Write-Ok 'apksigner: gueltig, …' }`

**Interfaces:**
- Consumes: nichts aus Task 1.
- Produces: `ARUCO_EXPECTED_CERT_SHA256` — gesetzt vergleicht `check-apk-release` den
  Fingerabdruck, ungesetzt meldet es nur. Task 7 und Task 9 setzen es.

**Kein eigener Befehl.** Die Spezifikation schlug in §5.2 ein `check-release-key` vor;
dieselbe Prüfung gehört aber dorthin, wo schon `apksigner verify --print-certs` läuft
und wo schon eine Aussage über den Schlüssel getroffen wird. Ein zweiter Befehl wäre
eine zweite Art, dasselbe zu tun (`AGENTS.md`, „Konventionen").

- [ ] **Step 1: Die Prüfung einfügen**

Nach diesem bestehenden Block:

```powershell
    if ((-not $Release) -and (-not $debugSigned)) {
        Write-Warn "Dieses Debug-APK traegt NICHT den Debug-Schluessel - unerwartet."
    }
```

einfügen:

```powershell
    # WELCHER Schluessel - und nicht nur "nicht der Debug-Schluessel".
    #
    # Die Zeilen darueber schliessen den einen falschen Schluessel aus, den das
    # SDK jedem Rechner mitgibt. Irgendein ANDERER faellt ihnen nicht auf, und
    # ein APK mit fremdem Schluessel installiert sich tadellos - es laesst sich
    # nur nie wieder aktualisieren. Deshalb der Fingerabdruck, und deshalb am
    # ERZEUGNIS: "assembleRelease lief durch" ist eine Aussage ueber den Bauweg.
    #
    # Ohne gesetzte Erwartung wird nichts verglichen. Auf diesem Rechner gibt es
    # genau einen Schluessel, und eine Zahl, die man von Hand pflegen muesste,
    # waere hier eine Fehlerquelle ohne Gegenwert. Die Werkbank setzt sie.
    if ($Release -and $env:ARUCO_EXPECTED_CERT_SHA256) {
        # keytool schreibt Grossbuchstaben mit Doppelpunkten, apksigner
        # Kleinbuchstaben ohne. Beide Formen auf dieselbe reduzieren, sonst
        # scheitert der Vergleich an der Schreibweise statt am Schluessel.
        $normalise = { param($text) ($text -replace '[^0-9A-Fa-f]', '').ToLowerInvariant() }
        $expectedCert = & $normalise $env:ARUCO_EXPECTED_CERT_SHA256
        $digestLine = $signature | Select-String 'certificate SHA-256 digest:' | Select-Object -First 1
        if (-not $digestLine) { throw 'apksigner nannte keinen SHA-256-Fingerabdruck.' }
        $actualCert = & $normalise ($digestLine.ToString() -replace '^.*digest:\s*', '')
        if ($actualCert -ne $expectedCert) {
            throw (@(
                'Das Release-APK traegt den FALSCHEN Schluessel.',
                "     erwartet: $expectedCert",
                "     gefunden: $actualCert",
                '     Ein anderer Schluessel heisst: kein Geraet nimmt diese Fassung als Aktualisierung an.'
            ) -join [Environment]::NewLine)
        }
        Write-Ok 'apksigner: Fingerabdruck stimmt mit der Erwartung ueberein'
    }
```

## Task 3: Die Werkzeugkette lässt sich von außen festnageln

`Get-CMakeAndNinja` holt beides aus der Visual-Studio-Installation, und der NDK-Wähler

Auf einem Läufer liegen drei NDKs (27, 28, 29), und „die höchste" wäre eine andere als

**Files:**
- Modify: `dev.ps1`, `Get-CMakeAndNinja` (bei `dev.ps1:352`)
- Modify: `dev.ps1`, NDK-Wähler in `Invoke-BuildCoreAndroid` (bei `dev.ps1:470`)

**Interfaces:**
- Produces: `ARUCO_CMAKE`, `ARUCO_NINJA`, `ARUCO_NDK_VERSION`. Task 7 setzt

  VS-Installation des Läufers die CMake-Komponente nicht mitbringt.

- [ ] **Step 1: `Get-CMakeAndNinja` umstellbar machen**

Die Funktion vollständig ersetzen durch:

```powershell
function Get-CMakeAndNinja {
    # Aus der Umgebung zuerst. Die VS-Installation eines Laeufers muss die
    # CMake-Komponente nicht mitbringen, und dann liegt beides schlicht im Pfad -
    # ein Abbruch waere hier eine Aussage ueber VS und nicht ueber das Projekt.
    if ($env:ARUCO_CMAKE -and $env:ARUCO_NINJA) {
        $fromEnv = [ordered]@{ CMake = $env:ARUCO_CMAKE; Ninja = $env:ARUCO_NINJA }
        foreach ($tool in $fromEnv.Values) {
            if (-not (Test-Path $tool)) { throw "Werkzeug aus der Umgebung fehlt: $tool" }
        }
        return $fromEnv
    }

    $install = Find-VcInstall
    $tools = [ordered]@{
        CMake = Join-Path $install 'Common7\IDE\CommonExtensions\Microsoft\CMake\CMake\bin\cmake.exe'
        Ninja = Join-Path $install 'Common7\IDE\CommonExtensions\Microsoft\CMake\Ninja\ninja.exe'
    }
    foreach ($tool in $tools.Values) {
        if (-not (Test-Path $tool)) {
            throw (@(
                "Werkzeug fehlt in $install : $tool",
                '     Liegen cmake und ninja woanders:  $env:ARUCO_CMAKE / $env:ARUCO_NINJA'
            ) -join [Environment]::NewLine)
        }
    }
    return $tools
}
```

```powershell
    # nennt sie in der Umgebung: eine Werkbank MUSS sie festnageln, sonst baut

    $ndkDirs = Get-ChildItem (Join-Path $sdk 'ndk') -Directory |
        Where-Object { Test-Path (Join-Path $_.FullName 'build\cmake\android.toolchain.cmake') }

        }
    } else {
        $ndk = $ndkDirs | Sort-Object Name -Descending | Select-Object -First 1
    }
    if (-not $ndk) { throw "Kein NDK mit android.toolchain.cmake unter $sdk\ndk gefunden." }
```

```python
"""Fassung und Beschreibung fuer die Werkbank aus dem Repo lesen.

Beides steht schon da: die Fassung in app/config.py, die Beschreibung in
CHANGELOG.md. Sie hier zu LESEN statt der Werkbank zu sagen, ist derselbe

cv2. Die Pruefaufgabe der Werkbank soll die Fassung lesen koennen, BEVOR 90 MB
OpenCV installiert sind - sonst kostet jeder Push nach master die volle
Einrichtung, auch einer, der gar keine Fassung ist. Gelesen wird dieselbe eine
Zeile; dass beide Wege dasselbe ergeben, haelt tests/test_release_notes.py fest.
"""

from __future__ import annotations

import argparse
import ast
import re
import sys
from pathlib import Path

ROOT = Path(__file__).resolve().parents[1]
CONFIG_PATH = ROOT / "app" / "config.py"
CHANGELOG_PATH = ROOT / "CHANGELOG.md"


def read_version() -> str:
    """APP_VERSION aus app/config.py holen, ohne das Modul auszufuehren."""
    tree = ast.parse(CONFIG_PATH.read_text(encoding="utf-8"), filename=str(CONFIG_PATH))
    for node in tree.body:
        if not isinstance(node, ast.Assign):
            continue
        for target in node.targets:
            if isinstance(target, ast.Name) and target.id == "APP_VERSION":
                return ast.literal_eval(node.value)
    raise KeyError(f"APP_VERSION steht nicht in {CONFIG_PATH}")


def extract_notes(changelog: str, version: str) -> str:
    """Den Abschnitt einer Fassung aus einem Keep-a-Changelog-Text holen.

    Ohne die Ueberschrift selbst: die Fassungsseite nennt die Fassung schon in
    ihrem Titel, und zweimal dieselbe Zeile liest sich wie ein Versehen.
    """
    # re.escape, weil der Punkt in "0.1.7" ein Punkt ist und kein Platzhalter.
    heading = re.compile(r"^## \[" + re.escape(version) + r"\].*$", re.MULTILINE)
    match = heading.search(changelog)
    if match is None:
        raise KeyError(version)

    following = re.compile(r"^## ", re.MULTILINE).search(changelog, match.end())
    end = following.start() if following else len(changelog)
    return changelog[match.end():end].strip()


def main(argv: list[str] | None = None) -> int:
    # Die Ausgabe geht in der Werkbank in eine Datei und nicht auf eine Konsole.
    # Ohne diese Zeile gilt dort cp1252, und das erste Sonderzeichen aus dem
    # Changelog bricht den Lauf ab (AGENTS.md, "Unicode auf der Konsole").
    sys.stdout.reconfigure(encoding="utf-8")

    parser = argparse.ArgumentParser(description="Fassung und Changelog-Abschnitt ausgeben.")
    what = parser.add_mutually_exclusive_group(required=True)
    what.add_argument("--version", action="store_true", help="nur die Fassungsnummer")
    what.add_argument("--notes", action="store_true", help="der Changelog-Abschnitt dazu")
    args = parser.parse_args(argv)

    version = read_version()
    if args.version:
        print(version)
        return 0

    try:
        print(extract_notes(CHANGELOG_PATH.read_text(encoding="utf-8"), version))
    except KeyError:
        print(
            f"CHANGELOG.md hat keinen Abschnitt fuer {version}. "
            "Eine Fassung ohne Beschreibung wird nicht ausgeliefert.",
            file=sys.stderr,
        )
        return 1
    return 0


if __name__ == "__main__":
    raise SystemExit(main())
```

## Task 6: Zusammengesetzte Aktion `setup-windows-toolchain`

**Files:**
- Create: `.github/actions/setup-windows-toolchain/action.yml`

**Interfaces:**
- Produces: eine Aktion mit den Eingaben `opencv-version` (Vorgabe `5.0.0`) und
  `inno-setup` (Vorgabe `false`). Setzt `OpenCV_DIR` für die folgenden Schritte.
  Task 8, 9 und 12 benutzen sie.

- [ ] **Step 1: Die Aktion schreiben**

```yaml
name: Windows-Werkzeugkette
description: >
  Python, Node, das OpenCV-Windows-SDK und auf Wunsch Inno Setup herrichten -
  alles, was dev.ps1 auf einem Windows-Laeufer vorfinden muss.

inputs:
  opencv-version:
    description: Fassung des OpenCV-Windows-SDK
    required: false
    default: '5.0.0'
  inno-setup:
    description: Inno Setup mitinstallieren (nur build-installer braucht es)
    required: false
    default: 'false'

runs:
  using: composite
  steps:
    - uses: actions/setup-python@v5
      with:
        python-version: '3.13'

    - uses: actions/setup-node@v4
      with:
        node-version: '22'
        cache: npm

    # Das venv ins Zwischenlager. Confirm-Deps in dev.ps1 legt es sonst bei
    # jedem Lauf neu an, und opencv-python-headless allein sind rund 90 MB.
    # Der Schluessel haengt an requirements.txt: aendert die sich, entsteht ein
    # neues Lager, und ein veraltetes kann gar nicht benutzt werden.
    - name: venv aus dem Zwischenlager
      uses: actions/cache@v4
      with:
        path: venv
        key: venv-${{ runner.os }}-py313-${{ hashFiles('requirements.txt') }}

    - name: OpenCV-SDK aus dem Zwischenlager
      id: opencv
      uses: actions/cache@v4
      with:
        path: ${{ runner.temp }}\opencv
        key: opencv-windows-${{ inputs.opencv-version }}

    # Das ist ein selbstentpackendes 7z-Archiv und KEIN Installer: -o<Ziel> -y
    # packt es aus, ohne irgendetwas in die Registrierung zu schreiben. Darin
    # liegt opencv/build/, und genau dort sucht Find-OpenCVDir die
    # OpenCVConfig.cmake.
    - name: OpenCV-SDK holen
      if: steps.opencv.outputs.cache-hit != 'true'
      shell: pwsh
      run: |
        $version = '${{ inputs.opencv-version }}'
        $url = "https://github.com/opencv/opencv/releases/download/$version/opencv-$version-windows.exe"
        $exe = Join-Path $env:RUNNER_TEMP 'opencv-sfx.exe'
        Write-Host "==> $url"
        Invoke-WebRequest -Uri $url -OutFile $exe
        & $exe -o"$env:RUNNER_TEMP" -y
        Remove-Item $exe

    - name: OpenCV_DIR bekanntgeben
      shell: pwsh
      run: |
        $dir = Join-Path $env:RUNNER_TEMP 'opencv\build'
        $marker = Join-Path $dir 'OpenCVConfig.cmake'
        if (-not (Test-Path $marker)) { throw "OpenCV liegt nicht, wo erwartet: $marker" }
        "OpenCV_DIR=$dir" | Out-File $env:GITHUB_ENV -Append -Encoding utf8

    - name: Inno Setup
      if: inputs.inno-setup == 'true'
      shell: pwsh
      run: choco install innosetup --no-progress -y
```

```yaml
description: >
  JDK, das festgenagelte NDK, das OpenCV-Android-SDK und - wenn ein Geheimnis
  gereicht wird - den Release-Schluessel herrichten.

inputs:
  ndk-version:
    description: Genau diese NDK-Fassung, nicht die hoechste vorhandene
    required: false
    default: '27.2.12479018'

    description: Fassung des OpenCV-Android-SDK
    required: false
    default: '5.0.0'
  keystore-base64:

    required: false
    default: ''

    description: Kennwort dazu
    required: false
    default: ''

    description: Fingerabdruck, den das fertige APK tragen muss
    required: false
    default: ''

runs:
  using: composite
  steps:
    - uses: actions/setup-java@v4
      with:
        distribution: temurin
        java-version: '17'

    # ANDROID_SDK_ROOT ausdruecklich in GITHUB_ENV schreiben, bevor es jemand
    # als ${{ env.ANDROID_SDK_ROOT }} liest.
    #
    # Das Laeuferbild setzt die Variable im Prozess, und ob der env-Kontext einer
    # zusammengesetzten Aktion sie dann schon kennt, ist nirgends zugesagt - ein
    # leerer Pfad im cache-Schritt sieht danach aus, als haette das
    # Zwischenlager nicht gegriffen, und laedt das NDK jedes Mal neu. Nach
    # dieser Zeile ist es zugesagt. ANDROID_HOME ist der aeltere Name derselben
    # Sache; dev.ps1 liest ANDROID_SDK_ROOT.
    - name: Das Android-SDK bekanntgeben
      shell: pwsh
      run: |
        $sdk = if ($env:ANDROID_SDK_ROOT) { $env:ANDROID_SDK_ROOT } else { $env:ANDROID_HOME }
        if (-not $sdk) { throw 'Weder ANDROID_SDK_ROOT noch ANDROID_HOME sind gesetzt.' }
        if (-not (Test-Path $sdk)) { throw "Das Android-SDK liegt nicht unter $sdk." }
        "ANDROID_SDK_ROOT=$sdk" | Out-File $env:GITHUB_ENV -Append -Encoding utf8

    # Genau diese NDK-Fassung. Auf dem Laeufer liegen mehrere, und dev.ps1
    # naehme sonst die hoechste - einen anderen Uebersetzer als den, mit dem auf
    # dem Entwicklerrechner gebaut wird. Der Unterschied faellt erst auf einem
    # Telefon auf, also wird er hier gar nicht erst zugelassen.
    - name: NDK aus dem Zwischenlager
      id: ndk
      uses: actions/cache@v4
      with:
        path: ${{ env.ANDROID_SDK_ROOT }}/ndk/${{ inputs.ndk-version }}
        key: ndk-${{ inputs.ndk-version }}

    - name: NDK holen
      if: steps.ndk.outputs.cache-hit != 'true'
      shell: pwsh
      run: |
        $sdkmanager = Join-Path $env:ANDROID_SDK_ROOT 'cmdline-tools\latest\bin\sdkmanager.bat'

    - name: OpenCV-Android-SDK holen

      run: |

        $dir = Join-Path $env:RUNNER_TEMP 'opencv-android'

        Invoke-WebRequest -Uri $url -OutFile $zip
        Expand-Archive -Path $zip -DestinationPath $dir -Force
        Remove-Item $zip

    - name: Werkzeugkette bekanntgeben
      shell: pwsh
      run: |
        $opencv = Join-Path $env:RUNNER_TEMP 'opencv-android'
        $marker = Join-Path $opencv 'OpenCV-android-sdk\sdk\native\jni\OpenCVConfig.cmake'

          "ARUCO_OPENCV_ANDROID=$opencv"
          "ARUCO_NDK_VERSION=${{ inputs.ndk-version }}"

    # Der Schluessel kommt aus dem Geheimnis in den Arbeitsbereich, und

    # neuen zu erfinden. Ohne diese Zeile waere ein leeres Geheimnis kein
    # Fehler, sondern eine Fassung mit fremder Signatur.
    - name: Release-Schluessel auspacken
      if: inputs.keystore-base64 != ''
      shell: pwsh
      env:
        KEYSTORE_BASE64: ${{ inputs.keystore-base64 }}
        KEYSTORE_PASSWORD: ${{ inputs.keystore-password }}
        EXPECTED_CERT: ${{ inputs.expected-cert-sha256 }}
      run: |
        if (-not $env:KEYSTORE_PASSWORD) { throw 'keystore-base64 gereicht, aber kein keystore-password.' }
        # Die Erwartung an den Fingerabdruck MUSS mitkommen. Ein leerer Wert ist
        # fuer dev.ps1 dasselbe wie gar keiner (PowerShell kennt keine leere
        # gesetzte Variable), und check-apk-release vergliche dann stillschweigend
        # nichts. Ein Schluessel wird hier ausgepackt - also wird auch geprueft,
        # dass hinterher jemand nachsehen kann, ob es der richtige war.

          (Join-Path $dir 'aruco-release.p12'),
          [Convert]::FromBase64String($env:KEYSTORE_BASE64))
        @(
          "ARUCO_SIGNING_DIR=$dir"
          'ARUCO_REQUIRE_EXISTING_KEY=1'
          "ARUCO_EXPECTED_CERT_SHA256=$env:EXPECTED_CERT"
        ) | Out-File $env:GITHUB_ENV -Append -Encoding utf8
        # Das Kennwort geht NICHT ueber GITHUB_ENV in eine Datei, sondern
        # ueber den Maskierungsweg in die Umgebung der folgenden Schritte.
        "::add-mask::$env:KEYSTORE_PASSWORD"
        "ARUCO_KEYSTORE_PASSWORD=$env:KEYSTORE_PASSWORD" | Out-File $env:GITHUB_ENV -Append -Encoding utf8
```

## Task 9: `build.yml` — die eine Baubeschreibung

**Files:**
- Create: `.github/workflows/build.yml`

**Interfaces:**
- Consumes: beide Aktionen aus Task 6 und 7.
- Produces: ein `workflow_call`-Ablauf mit der Eingabe `sign` (Boolean) und der Ausgabe
  `version`. Legt zwei Artefaktbündel ab: `windows-artifacts` (Installer + Browser-Bau)
  und `android-artifacts` (APK). Task 10 und Task 12 rufen ihn.

- [ ] **Step 1: Den Ablauf schreiben**

```yaml
name: Build

# NUR ueber workflow_call. Drei Anlaesse wollen dasselbe bauen (Fassung,
# Nachtbau, Handstart), und die Bauschritte stehen deshalb EINMAL hier statt
# dreimal nebeneinander - dieselbe Regel, die im Repo fuer dev.ps1 gilt.
on:
  workflow_call:
    inputs:
      sign:
        description: Das APK mit dem echten Schluessel signieren
        type: boolean
        required: false
        default: false
    secrets:
      ANDROID_KEYSTORE_P12_BASE64:
        required: false
      ANDROID_KEYSTORE_PASSWORD:
        required: false

permissions:
  contents: read

jobs:
  windows:
    name: build-windows
    runs-on: windows-latest
    steps:
      - uses: actions/checkout@v4
      - uses: ./.github/actions/setup-windows-toolchain
        with:
          inno-setup: 'true'

      # Ohne cv2 - deshalb liest release_notes.py mit ast (tools/release_notes.py).
      - name: Die Fassung lesen
        id: version
        shell: pwsh
        run: |
          $version = & python tools\release_notes.py --version
          if ($LASTEXITCODE -ne 0) { throw 'Die Fassung liess sich nicht lesen.' }
          "value=$version" | Out-File $env:GITHUB_OUTPUT -Append -Encoding utf8
          Write-Host "==> $version"

      - name: Die .exe bauen
        shell: pwsh
        run: .\dev.ps1 build-exe

      - name: Den Installer bauen
        shell: pwsh
        run: .\dev.ps1 build-installer

      - name: Den Browser-Bau zusammenstellen
        shell: pwsh
        run: .\dev.ps1 build-web

      # dist/web/ ist ein Baum; eine Fassungsseite haelt eine Datei. Also hier
      # packen und nicht erst beim Veroeffentlichen - dann traegt schon das
      # Artefakt den Namen, unter dem die Datei spaeter erscheint.
      - name: Den Browser-Bau packen
        shell: pwsh
        run: |
          $version = '${{ steps.version.outputs.value }}'
          Compress-Archive -Path dist\web\* -DestinationPath "dist\aruco-homographie-web-$version.zip" -Force

      - uses: actions/upload-artifact@v4
        with:
          name: windows-artifacts
          if-no-files-found: error
          path: |
            dist/ArUco-Homographie-Setup-*.exe
            dist/aruco-homographie-web-*.zip

  android:
    name: build-android
    runs-on: windows-latest
    steps:
      - uses: actions/checkout@v4
      - uses: ./.github/actions/setup-windows-toolchain
      - uses: ./.github/actions/setup-android-toolchain
        with:
          keystore-base64: ${{ inputs.sign && secrets.ANDROID_KEYSTORE_P12_BASE64 || '' }}
          keystore-password: ${{ inputs.sign && secrets.ANDROID_KEYSTORE_PASSWORD || '' }}
          expected-cert-sha256: ${{ vars.ANDROID_CERT_SHA256 }}

      # Ohne Geheimnis darf hier KEIN unsigniertes Erzeugnis entstehen, das
      # spaeter wie ein Release aussieht. Also frueh und ausdruecklich abbrechen.
      - name: Nachsehen, dass der Schluessel da ist
        if: inputs.sign
        shell: pwsh
        run: |
          if (-not $env:ARUCO_SIGNING_DIR) {
            throw 'sign=true, aber ANDROID_KEYSTORE_P12_BASE64 ist leer oder fehlt.'
          }
          # UND die Erwartung an den Fingerabdruck.
          #
          # dev.ps1 kann das nicht selbst: in PowerShell ist eine leere
          # Zuweisung dasselbe wie keine, und check-apk-release liest die
          # ungesetzte Erwartung als "nur melden". Ein falsch benanntes oder
          # leeres Geheimnis ergaebe damit ein GRUENES check-apk-release auf
          # einem Release-APK, dessen Schluessel nie verglichen wurde - genau
          # das Ergebnis, gegen das es die Pruefung gibt. Also faengt es der
          # Aufrufer, und der ist hier.
          if (-not $env:ARUCO_EXPECTED_CERT_SHA256) {
            throw 'sign=true, aber die Variable ANDROID_CERT_SHA256 ist leer oder fehlt.'
          }

      - name: Das signierte APK bauen
        if: inputs.sign
        shell: pwsh
        run: .\dev.ps1 build-apk-release

      - name: Das Debug-APK bauen
        if: ${{ !inputs.sign }}
        shell: pwsh
        run: .\dev.ps1 build-apk

      # Unter dem Namen, unter dem die Datei auf der Fassungsseite erscheint -
      # und in ein EIGENES Verzeichnis.
      #
      # Nicht in android/out/ liegen lassen: dort liegt daneben weiter
      # aruco-homographie-release.apk, und ein Muster wie
      # "aruco-homographie-*.apk" nähme beide mit. Auf der Fassungsseite
      # stuenden dann zwei APKs derselben Fassung unter verschiedenen Namen -
      # genau der Zustand, den das Weglassen des Debug-APK beseitigen soll.
      - name: Nach der Fassung benennen
        shell: pwsh
        run: |
          $version = & python tools\release_notes.py --version
          if ($LASTEXITCODE -ne 0) { throw 'Die Fassung liess sich nicht lesen.' }
          $signed = '${{ inputs.sign }}' -eq 'true'
          $source = if ($signed) {
            'android\out\aruco-homographie-release.apk'
          } else {
            'android\out\aruco-homographie-debug.apk'
          }
          $suffix = if ($signed) { '' } else { '-debug' }
          New-Item -ItemType Directory -Path 'publish' -Force | Out-Null
          Copy-Item $source "publish\aruco-homographie-$version$suffix.apk"
          Get-ChildItem publish | Select-Object Name, Length

      - uses: actions/upload-artifact@v4
        with:
          name: android-artifacts
          if-no-files-found: error
          path: publish/*.apk
```

## Task 10: `release.yml` — Marke, Fassung, Beschreibung

**Files:**
- Create: `.github/workflows/release.yml`

**Interfaces:**
- Consumes: `build.yml` aus Task 9, `tools/release_notes.py` aus Task 5.
- Produces: die Aufgabe `release`, an die Task 11 die F-Droid-Aufgabe hängt.

- [ ] **Step 1: Den Ablauf schreiben**

```yaml
name: Release

# Ein Push nach master IST eine Fassung - master bekommt nur Release-PRs
# (docs/contributing/git.md, Abschnitt 7). Verlassen wird sich darauf nicht:
# die Wache prueft nach.
on:
  push:
    branches: [master]

permissions:
  contents: write

jobs:
  # Die Wache. Sie laeuft auf Ubuntu und ohne OpenCV - deshalb liest
  # release_notes.py APP_VERSION mit ast statt mit import. Eine halbe Minute
  # hier spart 25 Minuten Bauzeit fuer einen Push, der gar keine Fassung ist.
  guard:
    name: guard
    runs-on: ubuntu-latest
    outputs:
      version: ${{ steps.check.outputs.version }}
      fresh: ${{ steps.check.outputs.fresh }}
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0   # die Marken werden gebraucht

      - uses: actions/setup-python@v5
        with:
          python-version: '3.13'

      - name: Fassung, Marke und Changelog pruefen
        id: check
        run: |
          set -euo pipefail
          version="$(python tools/release_notes.py --version)"
          echo "==> APP_VERSION ist $version"
          echo "version=$version" >> "$GITHUB_OUTPUT"

          # Schon ausgeliefert? Dann war dieser Push keine Fassung, sondern
          # eine Korrektur - und dann passiert hier NICHTS. Das macht den
          # ganzen Ablauf wiederholbar: zweimal derselbe Push, einmal Wirkung.
          if git rev-parse "v$version" >/dev/null 2>&1; then
            echo "==> v$version gibt es schon - nichts zu tun."
            echo "fresh=false" >> "$GITHUB_OUTPUT"
            exit 0
          fi

          # Eine Fassung ohne Beschreibung wird nicht ausgeliefert. Der
          # Rücklaufwert von release_notes.py ist hier die ganze Pruefung.
          python tools/release_notes.py --notes > /dev/null
          echo "fresh=true" >> "$GITHUB_OUTPUT"

  build:
    needs: guard
    if: needs.guard.outputs.fresh == 'true'
    uses: ./.github/workflows/build.yml
    with:
      sign: true
    secrets:
      ANDROID_KEYSTORE_P12_BASE64: ${{ secrets.ANDROID_KEYSTORE_P12_BASE64 }}
      ANDROID_KEYSTORE_PASSWORD: ${{ secrets.ANDROID_KEYSTORE_PASSWORD }}

  release:
    name: release
    needs: [guard, build]
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with:
          python-version: '3.13'

      - uses: actions/download-artifact@v4
        with:
          pattern: '*-artifacts'
          merge-multiple: true
          path: artifacts

      # Die Beschreibung kommt aus CHANGELOG.md und nicht aus der Commit-Liste.
      # Was eine Fassung ENTHAELT, sagt der Changelog - der Release-PR traegt
      # einen einzigen Squash-Commit und wuesste es gar nicht
      # (docs/contributing/git.md, Abschnitt 7).
      - name: Die Beschreibung holen
        run: python tools/release_notes.py --notes > release-notes.md

      - name: Nachsehen, was veroeffentlicht wird
        run: ls -lh artifacts

      - name: Marke und Fassung anlegen
        env:
          GH_TOKEN: ${{ github.token }}
          VERSION: ${{ needs.guard.outputs.version }}
        run: |
          set -euo pipefail
          gh release create "v$VERSION" \
            --title "v$VERSION" \
            --notes-file release-notes.md \
            --target "$GITHUB_SHA" \
            artifacts/*
```

Anmerkung: `gh release create` legt die Marke selbst an (`--target`), deshalb kein
eigener `git tag`-Schritt. Eine Marke, die niemand setzt, kann auch niemand vergessen.

- [ ] **Step 2: Die Wache prüfen, ohne eine Fassung auszuliefern**

`release.yml` löst nur auf `master` aus, und dorthin wird jetzt nicht gepusht. Geprüft
wird die Wache deshalb örtlich, mit denselben Befehlen:

```powershell
.\venv\Scripts\python.exe tools\release_notes.py --version
git rev-parse v0.1.7-alpha
```

Erwartet: `0.1.7-alpha`, und die Marke existiert — also würde die Wache `fresh=false`
melden und nichts tun. Genau das ist das gewünschte Verhalten für einen Push, der die
Fassung nicht erhöht.

Und der andere Fall:

```powershell
git rev-parse v9.9.9-alpha
```

Erwartet: `fatal: ambiguous argument 'v9.9.9-alpha': unknown revision` — also der Weg,
auf dem `fresh=true` entsteht.

- [ ] **Step 3: Commit**

Betreff: `ci: publish a release when master moves to a new version`

Rumpf: warum die Wache existiert (ein Push nach master muss keine Fassung sein), warum
die Beschreibung aus dem Changelog kommt, und warum `gh release create` die Marke setzt.

## Task 12: `nightly.yml`

**Files:**
- Create: `.github/workflows/nightly.yml`

**Interfaces:**
- Consumes: `build.yml` aus Task 9.

- [ ] **Step 1: Den Ablauf schreiben**

```yaml
name: Nightly

on:
  schedule:
    - cron: '17 2 * * *'   # 02:17 UTC - nicht zur vollen Stunde, da draengeln sich alle
  workflow_dispatch:

permissions:
  contents: write

jobs:
  # Nur bauen, wenn develop sich bewegt hat. Ein Nachtbau desselben Baums sagt
  # nichts Neues und kostet 25 Minuten Laeuferzeit.
  changed:
    name: changed
    runs-on: ubuntu-latest
    outputs:
      go: ${{ steps.check.outputs.go }}
    steps:
      - uses: actions/checkout@v4
        with:
          ref: develop
          fetch-depth: 0

      - id: check
        env:
          GH_TOKEN: ${{ github.token }}
        run: |
          set -euo pipefail
          head="$(git rev-parse HEAD)"
          # Woran der letzte Nachtbau haengt: der Commit, den die rollende
          # Vorabfassung traegt. Gibt es sie nicht, ist es der erste Lauf.
          previous="$(gh release view nightly --json targetCommitish --jq .targetCommitish 2>/dev/null || echo '')"
          echo "==> develop: $head"
          echo "==> zuletzt: ${previous:-(noch nie)}"
          if [ "$head" = "$previous" ]; then
            echo 'develop hat sich nicht bewegt - nichts zu tun.'
            echo 'go=false' >> "$GITHUB_OUTPUT"
          else
            echo 'go=true' >> "$GITHUB_OUTPUT"
          fi

  build:
    needs: changed
    if: needs.changed.outputs.go == 'true'
    uses: ./.github/workflows/build.yml
    with:
      sign: false

  publish:
    name: publish
    needs: [changed, build]
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          ref: develop

      - uses: actions/download-artifact@v4
        with:
          pattern: '*-artifacts'
          merge-multiple: true
          path: artifacts

      # Eine rollende Vorabfassung, kein wachsender Stapel. Die alte wird
      # geloescht und neu angelegt - sonst sammeln sich 365 Nachtstaende im Jahr,
      # und der neueste ist zwischen ihnen nicht zu finden.
      - name: Die rollende Vorabfassung ersetzen
        env:
          GH_TOKEN: ${{ github.token }}
        run: |
          set -euo pipefail
          gh release delete nightly --yes --cleanup-tag || true
          gh release create nightly \
            --title "Nachtbau aus develop" \
            --notes "Automatisch gebaut aus develop ($(git rev-parse --short HEAD), $(date -u '+%Y-%m-%d %H:%M UTC')).

          **Kein Auslieferungsstand.** Das APK traegt den DEBUG-Schluessel und laesst
          sich nicht ueber eine installierte Fassung aus dem F-Droid-Bestand legen -
          erst deinstallieren." \
            --prerelease \
            --target "$(git rev-parse HEAD)" \
            artifacts/*
```

## Was dieser Plan nicht tut

- **Kein Play Store — und keine Vorbereitung darauf.** Nicht „noch nicht", sondern gar
  nicht: die Begründung steht in `docs/publishing/README.md` §4. Deshalb entfällt Task 4.
- **Keine Bewerbung beim offiziellen F-Droid.** Die Lizenz ist seit `669424c` da
  (GPL-3.0-or-later); übrig bleibt das vorgebaute OpenCV-Android-SDK. Das ist ein Umbau
  am Bau (`docs/publishing/f-droid.md`, Weg A), keine CI-Frage.
- **Keine Signatur der Windows-`.exe`.** SmartScreen nennt weiterhin keinen Herausgeber.
- **Kein Beweis über Millimeter.** Die Werkbank baut und zählt nach; sie fotografiert
  nichts. Die Kette Foto → Marker → Millimeter bleibt auf Android unbelegt, und ein
  grüner Lauf darf nicht als Gegenteil gelesen werden.
